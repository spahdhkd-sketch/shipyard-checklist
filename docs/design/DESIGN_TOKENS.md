# GS Safety 디자인 토큰

이 문서는 `assets/css/styles-v2.css`의 `:root`를 단일 토큰 원본으로 정의한다. 기존 `--color-*`, `--poster-*`, `--ink`, `--line` 변수는 단계적 전환을 위한 호환 별칭이며, 새 스타일은 `--ds-*` 토큰을 사용한다.

## 색상

| 역할 | 토큰 | 값 | 용도 |
| --- | --- | --- | --- |
| 셸 네이비 | `--ds-color-navy-950` | `#07162F` | 사이드바, 모바일 헤더, 어두운 표면 |
| 콘텐츠 네이비 | `--ds-color-navy-800` | `#17324D` | 제목, 카드 강조선 |
| 크림 | `--ds-color-cream-50` | `#F8F1E8` | 작업 단계와 따뜻한 보조 표면 |
| 크림 라이트 | `--ds-color-cream-25` | `#FFF8E7` | 우선 조치 배경 |
| 청록 | `--ds-color-teal-700` | `#0F766E` | 주 행동, 포커스, 활성 상태 |
| 오렌지 | `--ds-color-orange-700` | `#D97706` | 경고 테두리와 비텍스트 강조 |
| 경고 텍스트 | `--ds-color-amber-800` | `#8F6430` | 밝은 경고 표면의 본문·상태 문구 |
| 성공 | `--ds-color-success-700` | `#3F7A50` | 정상, 완료 |
| 위험 | `--ds-color-danger-800` | `#B42318` | 위험, 파괴적 행동 |
| 정보 | `--ds-color-info-700` | `#2E5DA6` | 링크와 안내 |

색상만으로 상태를 전달하지 않는다. 모든 상태는 텍스트나 아이콘을 함께 제공하고, 본문 대비는 WCAG AA를 충족해야 한다.

상태 텍스트는 `경고 텍스트 / 경고 표면`, `위험 텍스트 / 위험 표면`, `콘텐츠 네이비 / 크림`처럼 함께 검증된 전경·배경 쌍을 사용한다. 오렌지는 일반 크기 텍스트 색으로 사용하지 않는다.

## 글꼴

기본 글꼴은 `--ds-font-family-sans`다.

```css
font-family: "Noto Sans KR", Arial, "Apple SD Gothic Neo", sans-serif;
```

오프라인 PWA 동작을 유지하기 위해 외부 웹폰트를 호출하지 않는다. 기기에 Noto Sans KR이 없으면 시스템 대체 글꼴을 사용한다.

## 간격

새 레이아웃의 기본 간격은 다음 다섯 단계만 사용한다.

| 토큰 | 값 |
| --- | --- |
| `--ds-space-8` | `8px` |
| `--ds-space-12` | `12px` |
| `--ds-space-16` | `16px` |
| `--ds-space-24` | `24px` |
| `--ds-space-32` | `32px` |

`3·4·6·10·14·18·20·22px` 토큰은 기존 UI의 계산값을 보존하기 위한 호환 값이다. 새 컴포넌트에는 사용하지 않는다.

## 테두리·라운드·그림자

- 기본 테두리: `--ds-border-width-default`, `--ds-color-line`
- 구획·포커스·상태 테두리: `--ds-border-width-section`, `--ds-border-width-focus`, `--ds-border-width-emphasis`
- 주요 강조 테두리: `--ds-border-width-accent`
- 컨트롤 라운드: `--ds-radius-10`
- 내부 카드 라운드: `--ds-radius-12`
- KPI 라운드: `--ds-radius-14`
- 주요 카드 라운드: `--ds-radius-16`
- 배지 라운드: `--ds-radius-pill`
- 기본 카드 그림자: `--ds-shadow-card`
- 보조 표면 그림자: `--ds-shadow-subtle`
- 모달 그림자: `--ds-shadow-dialog`

그림자는 정보 위계를 보조할 때만 사용한다. 위험 상태는 그림자 대신 위험색 테두리와 명시적인 문구로 구분한다.

## 반응형 기준

CSS 사용자 정의 속성은 미디어 쿼리 조건에서 사용할 수 없으므로 아래 숫자는 CSS와 테스트에서 동일하게 유지한다.

| 구간 | 기준 |
| --- | --- |
| PC 셸 | `min-width: 921px` |
| 태블릿·모바일 셸 | `max-width: 920px` |
| 휴대전화 재배치 | `max-width: 760px` |
| 좁은 휴대전화 | `max-width: 420px` |
| 최소 폭 보정 | `max-width: 360px` |

필수 회귀검사 폭은 `360px`, `390px`, `430px`다. 390px과 430px은 별도 미디어 쿼리를 만드는 기준이 아니라, 유동 레이아웃이 중간 폭에서도 유지되는지 확인하는 검증 폭이다.

## 적용 규칙

1. 새 색상이나 간격을 만들기 전에 기존 `--ds-*` 토큰을 찾는다.
2. 기능 CSS에는 원시 색상값을 추가하지 않는다. 기능별 의미가 필요하면 전역 토큰을 참조하는 지역 별칭을 만든다.
3. `--poster-*` 이름은 서약·통계·관리 화면의 호환 API로 유지하되 값은 전역 토큰에서 가져온다.
4. 터치 가능한 주요 컨트롤은 `--ds-touch-target-min`인 `44px` 이상으로 만든다.
5. 토큰 값을 바꿀 때는 PC와 360·390·430px에서 사이드바, 하단 메뉴, 제목, KPI, 모달을 함께 확인한다.

## 공통 데이터 화면

서약·통계·관리는 같은 데이터 신뢰 계약을 사용한다.

- `data-context`: 페이지 제목, 업무 기준 날짜, 최종 반영 시각, 최신·이전·오프라인 상태를 한곳에 표시한다.
- `data-surface-state`: 로딩·오류·빈 화면·이전 데이터·오프라인 안내와 범위가 정해진 재시도를 표시한다.
- 로딩·오류·빈 화면은 실제처럼 보이는 KPI, 분모, 목록, 내보내기 동작을 함께 숨긴다.
- 이전 데이터와 오프라인 상태는 마지막으로 확정된 시각을 표시하고, 최신 데이터가 필요한 수정·발송 동작을 비활성화한다.

| 상태 | 표시 규칙 | 행동 규칙 |
| --- | --- | --- |
| 로딩 | 숫자 대신 스켈레톤과 불러오는 중 안내 | 내보내기·수정·발송 비활성화 |
| 확정 | 기준 날짜, 최종 반영 시각, KPI·목록 표시 | 권한과 업무 규칙에 따라 활성화 |
| 오류 | 오류 안내와 해당 데이터 범위의 다시 시도 | 이전 값을 최신처럼 표시하지 않음 |
| 이전 데이터 | 마지막 확정 값과 이전 데이터 배지 | 최신성이 필요한 행동 비활성화 |
| 오프라인 | 오프라인 및 마지막 반영 시각 명시 | 서버 변경 행동 비활성화 |
| 빈 화면 | 권위 있는 0건 결과임을 안내 | 파괴적 행동을 제안하지 않음 |

## 모바일 화면 구조

- 서약·통계·관리의 핵심 KPI는 `360px`, `390px`, `430px`에서 2×2로 유지한다. 글자는 줄임표보다 자연스러운 두 줄을 우선하며 가로 스크롤을 만들지 않는다.
- 관리 화면은 PC에서 마스터–상세를 유지하고, 휴대전화에서는 `목록 → 전체화면 상세`로 전환한다.
- 상세를 열면 선택한 레코드 하나만 표시하고 초점을 뒤로 가기 또는 상세 제목으로 이동한다. 뒤로 가기는 목록의 원래 항목과 스크롤 위치를 복원한다.
- 전체화면 상세가 열린 동안 모바일 하단 메뉴는 숨기고 safe-area 여백을 적용한다. 마지막 버튼과 입력은 화면 하단에 가려지지 않아야 한다.
- 서약과 통계는 이미 존재하는 날짜·레코드 상세 이동을 유지한다. 별도 상세 데이터가 없는 카드에 가짜 상세 화면을 만들지 않는다.
